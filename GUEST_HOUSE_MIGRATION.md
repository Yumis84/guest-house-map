# Гостевые дома ↔ сауны: схема адаптации n8n

## Что уже подготовлено в ветке

- отдельный интерфейс гостевых домов;
- карта и каталог;
- избранное;
- карточка объекта;
- форма бронирования;
- экран AI-помощника;
- локальная модель заявки, совместимая по смыслу с таблицей бронирований гостевых домов.

## Гостевые дома: базовая модель бронирования

- booking_id
- house_id
- Название_дома
- Имя_гостя
- Телефон
- Email_гостя
- Дата_заезда
- Дата_выезда
- Количество_гостей
- Стоимость
- Статус
- Источник
- Дата_создания

## Адаптация этого workflow под сауны и бани

Рекомендуется не менять рабочий workflow гостевых домов, а создать его копию.

Соответствие полей:

- house_id → venue_id
- Название_дома → Название_заведения
- Дата_заезда → Дата
- Дата_выезда → Время_начала + Длительность_часов
- Количество_гостей → Количество_гостей
- Имя_гостя → Имя_клиента
- Телефон → Телефон
- Email_гостя → Email (необязательно)
- Стоимость → Стоимость
- Статус → Статус
- Источник → Источник
- Дата_создания → Дата_создания

Дополнительно для саун:

- выбранный зал / номер сауны;
- бассейн / хаммам / баня на дровах и другие пожелания;
- минимальная длительность;
- цена за час;
- желаемое время;
- комментарий клиента.

## Логика AI-агента для саун

1. Определить город и пожелания пользователя.
2. Подобрать подходящие заведения из каталога.
3. Уточнить дату, время, длительность и число гостей.
4. Проверить доступность выбранного заведения.
5. Рассчитать ориентировочную стоимость.
6. Получить имя и телефон клиента.
7. Создать бронирование / заявку.
8. Вернуть подтверждение и статус в чат.

## Что нужно для подключения готового workflow гостевых домов

Нужен webhook URL или JSON-экспорт рабочего n8n workflow. После этого экран AI-помощника можно подключить к реальному workflow, а его копию адаптировать под сауны.
