## Кандидаты, не включение production

`sql/widget-v2-config.CANDIDATE.sql` и `sql/widget-v2-requests.CANDIDATE.sql` — отдельные, НЕ применённые файлы, не лежат в автоматических migrations. Не изменяют старые таблицы, auth, функции и политики. Требуют проверки реальных типов и RLS существующей модели. Локальные тесты используют изолированную БД с синтетической схемой; не доказывают совместимость production.

Публичная конфигурация не содержит company_id, owner_id, unit_id, внутреннее имя и контакты. Запись разрешена только owner/admin текущей компании с повторной проверкой принадлежности unit. Привязка существующего виджета неизменяема: для другого объекта создаётся новый. Черновик не виден публично. Публикация увеличивает версию; установка с постоянным ID получает новый снимок при следующей загрузке страницы. Предыдущий опубликованный снимок сохраняется для ручного восстановления через новый draft/publish.

Новые заявки хранятся отдельно от реальных бронирований. По умолчанию нет ни одной записи activation, hold_minutes не выбран, inventory adapter выбрасывает ошибку. Нельзя считать занятость загруженной при ошибке. Объект должен быть published и unit active. Ни один legacy RPC не отзывается этим кандидатом. Подключение прямого публичного вызова V2 submit запрещено ACL: только service_role через Edge.

До включения обязательны: одобрение CAPTCHA и policy URL; выбор правила pending; полный адаптер existing bookings/holds/blocks; согласованный общий lock для старых writers; lifecycle подтверждения/отклонения и inbox владельца; реальный тест гонок на staging; проверка доступа двух независимых владельцев; план хранения/удаления PII и очистки rate buckets; rollback. Без этого новый публичный экран показывает недоступность приёма, а не свободные даты.

## Решения владельца

1. CAPTCHA: Turnstile как подготовленный адаптер или другой сервис с проверкой доступности для аудитории.
2. Pending: заявки без удержания, короткое удержание или 24 часа. До решения нет активного значения.
3. Утверждённая ссылка на политику и проверка хранения/сроков удаления данных специалистом.
4. Нужен ли запрет чужих embedding-сайтов: тогда потребуется хостинг с HTTP CSP. GitHub Pages пока остаётся без такой гарантии.
5. Брендинг, цены/фото/мультиобъектность и SaaS — последующие решения, не условия безопасной разработки черновиков.
