# Персональные данные гостей — проект на отдельное утверждение

Не утверждено владельцем. Это проект продуктовых правил, не юридическое заключение и не готовая к публикации политика. Реальные данные в стенде запрещены.

Предлагаемые поля: имя, телефон, даты, число гостей, комментарий, версия согласия/политики и время согласия. Не собирать паспорт, платёжные данные, здоровье и другие избыточные сведения. Запретить гостям вносить чувствительные данные в комментарий. Полные контакты доступны только owner/admin при раскрытии карточки; раскрытие записывается в журнал. Список показывает маску телефона.

Предлагаемые сроки ДЛЯ ОБСУЖДЕНИЯ: неподтверждённые/отклонённые заявки — 90 дней от последнего решения; контакты отменённой брони — 90 дней после отмены; контакты завершённого проживания — 180 дней после выезда. Анонимизированные операционные события — 12 месяцев. Просроченные rate buckets — удалить через сутки после истечения. Нужные бухгалтерские/договорные документы могут иметь иной обязательный срок, который должен определить специалист.

Удаление контактов отделить от неизменяемого факта бронирования и журнала: сначала ограничение доступа, затем удаление/обезличивание по утверждённому регламенту, запись события без исходного телефона/имени. Обрабатывать запросы субъекта через проверяемый канал; не раскрывать наличие брони посторонним. Backup retention и восстановление должны учитывать повторное применение удалений.

Перед публикацией нужны: юридическое имя и контакты оператора, законные основания, перечень обработчиков/стран, проверка локализации и трансграничной передачи, адрес политики, текст согласия, порядок отзыва/обращений, согласованные сроки хранения и backup deletion. Supabase/Turnstile и другие внешние обработчики подлежат отдельной правовой проверке. До утверждения сроков автоматическое удаление гостевых контактов не включается; SQL-кандидат чистит только rate buckets.
