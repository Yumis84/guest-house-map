# Виджет бронирования в кабинете

Страница: `owner.html#widget`. Использует существующую проверку сессии и список объектов из `loadAccessibleProperties`. Новых запросов прав или записей в БД нет.

## Проверенный механизм (24.10.2026)

На https://saned039.github.io/stepan/ установлен iframe:
`https://yumis84.github.io/guest-house-map/widget/booking.html?v=20261021capacity8&property=4372d741-eab4-4c42-9ddc-88f78368f9b6`.
Адрес возвращает HTTP 200. Календарь и форма используют существующие `stepan_widget_blocks` и `submit_stepan_booking`. Параметр property в существующем виджете не выбирает другой объект: ID и RPC жёстко привязаны к Степану.

Поэтому генератор выдаёт код только для подтверждённого ID Степана, если он входит в загруженный список доступных объектов. Остальные объекты видны в списке, но предпросмотр и копирование для них отключены. Добавлять поддержку других домов можно только после появления публичного источника дат и механизма заявки для соответствующего объекта.

Три представления используют один действующий endpoint:
- Календарь с формой — существующий iframe целиком.
- Компактная форма — раскрывающийся блок с тем же iframe; новая форма или передача дат через неподдерживаемые параметры не изобретаются.
- Кнопка — ссылка на ту же форму в новой вкладке с `noopener noreferrer`.

Настройки цвета/скругления относятся к обрамлению, summary и кнопке. Внутренний дизайн календаря не меняется. Ширина ограничена контейнером; высота iframe начинается с 1100 px, затем обновляется с запасом 24 px. Каждый экземпляр кабинета создаёт уникальный ID. Для нескольких вставок генерируйте код в отдельных вкладках. Обработчик проверяет origin, source конкретного iframe, тип сообщения, конечность и диапазон высоты 350–3000 px. Вставлять весь код целиком; конструктор сайта должен разрешать script.

## Проверки

`node owner-widget.test.mjs` — три формата, разрешённый URL/объект, отклонение некорректных значений и HTML/JS-инъекций, проверки postMessage.

`node owner-widget.browser.test.mjs` — Playwright + Chromium; при необходимости задайте `PLAYWRIGHT_MODULE` (абсолютный путь к playwright/index.mjs) и `BROWSER_EXECUTABLE` (путь к Chromium/Edge). Проверяются ширины 1440 и 375 px, переход в раздел, три варианта предпросмотра, отсутствие горизонтального переполнения, неверные настройки, неподключённый объект, перенаправление без сессии. Скриншоты сохраняются локально в `test-results/`.

В браузерных тестах используются тестовая сессия, список объектов и ответ дат. HTML существующего виджета загружается из репозитория; отправка production-заявок запрещена тестом. Это не проверка реального входа пользователя или доставки заявки. Production, SQL, файлы авторизации и оба существующих виджета не изменяются.

Известный сбой до изменения: `node owner-dashboard.test.mjs` ожидает объединение property_members/company_members (`p1, shared, p2`), тогда как существующий owner-access.js сознательно использует только company_members (`p1, shared`). Эти файлы в данной ветке не меняются; исправление теста/модели доступа вне этой задачи.
